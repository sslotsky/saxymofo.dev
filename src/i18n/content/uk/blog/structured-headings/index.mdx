Як і багато історій, ця починається з того, що я провалив
технічну співбесіду. Багато років тому я мав завдання на
живе програмування в якійсь компанії, назви якої вже не
пам’ятаю, але ніколи не забуду, як хвилювався і як мені було
соромно, коли зрозумів, що не можу розв’язати задачу.
Чесно кажучи, я часто не бачу одразу правильного розв’язку
простих алгоритмічних задач. Мені справді потрібен час, щоб
усе «настоялося», перш ніж настане момент осяяння!

Іноді я ще кілька днів після співбесіди не можу викинути
задачу з голови й зрештою розв’язую її. Це, до речі, не той
випадок 😂 але нещодавно я знову натрапив на цю задачу й
розібрався. Повільно. Ідеться про цілий день мого життя.
Можливо, я й не видатний програміст, але, як на мене,
несправедливо, що стільки інтерв’юерів чекають від нас
розв’язку подібних задач лише за годину.

Любий читачу, зважай, що розв’язувати цю задачу мені не було
потреби. Її вже розв’язали за мене за допомогою
[плагіна][rehype-toc]. Але коли я впізнав у ній ту саму
задачу з тієї жахливої співбесіди багато років тому, мені
захотілося її розв’язати — здебільшого щоб довести собі, що
можу, але ще й щоб поділитися розв’язком тут, бо мені
приносить величезне задоволення спойлерити інтерв’юерам із
несправедливими очікуваннями. Якщо тобі колись трапиться
таке питання на співбесіді, сподіваюся, після цього допису
ти будеш краще підготовлений.

## Задача

У цій задачі нам дано впорядкований список заголовків, який
треба перетворити на дерево для змісту (Table Of Contents,
TOC) — на кшталт того, що показується праворуч на цій
сторінці на широкому екрані. Припустімо, маємо список тегів
заголовків у тому порядку, в якому вони йдуть на сторінці.

```ts
const orderedHeadings = [
  "h1",
  "h2",
  "h2",
  "h3",
  "h4",
  "h2",
];
```

Цей список треба перетворити на зміст зі структурою, яка
має приблизно такий вигляд:

```ts
return [
  {
    tag: "h1",
    children: [
      {
        tag: "h2",
        children: [],
      },
      {
        tag: "h2",
        children: [
          {
            tag: "h3",
            children: [
              {
                tag: "h4",
                children: [],
              },
            ],
          },
        ],
      },
      {
        tag: "h2",
        children: [],
      },
    ],
  },
];
```

Можливо, ти набагато сильніший програміст, ніж я, і вже
бачиш досить простий розв’язок. Можливо, ти також знаєш, що
для контенту в mdx [для цього вже є плагіни][rehype-toc].
Але, звісно, у межах цієї задачі це було б шахрайством. То
як же розв’язати її вручну?

## Розв’язок

Мій великий програмістський мозок часто переконує мене, що
для будь-якого перетворення списків існує рекурсивний
незмінний розв’язок. Може, так і є, але цього разу я такого
не знайшов. Я витратив на спроби _дуже_ багато часу,
особливо зважаючи на те, що зміст у мене _вже був_ після
підключення [плагіна для mdx][rehype-toc]. Тож коли запрацював
розв’язок із циклом і мутаціями, я на цьому зупинився.

Зрештою я зрозумів, що для будь-якого заголовка в списку
легко переглянути решту списку й визначити, яким має бути
його _батьківський_ елемент або що батьківського елемента
немає зовсім. Якщо його знайдено, вузол можна додати до
дочірніх елементів батьківського. Ось... загалом, і все.

### Приклади

Візьмімо заголовки, що йдуть на сторінці в такому порядку.

```plaintext
0 - h1
1 - h2
2 - h2
3 - h3
4 - h4
5 - h4
6 - h3
7 - h2
```

Який батьківський елемент у елемента з індексом 7? Це `h2`,
тож треба лише йти списком назад, доки не знайдемо `h1`, —
ним виявляється перший елемент списку.

А який батьківський елемент у елемента з індексом 5? Це
`h4`, сусід `h4` з індексом 4. В обох той самий батьківський
елемент — `h3` з індексом 3.

Перший елемент списку не має батьківського. Звісно, ми
знаємо, що `h1` — заголовок верхнього рівня, але що, якби в
нашому списку взагалі не було тегів `h1`?

```plaintext
0 - h2
1 - h2
2 - h3
```

Розглянувши елемент з індексом 1, ми мусимо дійти висновку,
що це заголовок верхнього рівня, бо, йдучи списком назад, ми
не знайдемо елемента з меншим номером заголовка. У цьому
прикладі два вузли верхнього рівня, а `h3` з індексом 2 —
дочірній елемент `h2` з індексом 1.

### Знаходимо батьківський елемент

Тепер, коли задача стала зрозумілішою, напишімо код, який
пройде списком і визначить батьківський елемент. Замість
масиву рядків на кшталт `h1` і `h2` у нас будуть об’єкти з
властивістю `level` і текстом заголовка `text`. Ми не
перевірятимемо правильність семантики заголовків: наприклад,
нашому коду байдуже, якщо `h5` іде після `h3`. Це ми
залишимо на совісті автора контенту.

```ts
interface ContentHeading {
  level: item.level;
  text: item.text;
}

export function structure(list: Array<ContentHeading>) {
  // Loop backwards through the list
  for (let i = list.length - 1; i > -1; i--) {
    const item = list[i];
    let j = i - 1;
    let prev = list.at(j);
    let parent = null;

    // Start looking through the previous items. Keep going until
    // you find an item with a lower level than the current item.
    if (prev && item.level > prev.level) {
      parent = prev;
    } else {
      while (prev && item.level <= prev.level) {
        prev = list.at(--j);
      }

      if (prev) {
        parent = prev;
      }
    }
  }
}
```

Цей код знайде батьківський елемент для кожного елемента,
але нічого з цією інформацією не зробить. Завершімо: додамо
дочірні елементи батьківським і повернемо вузли верхнього
рівня.

### Перебудовуємо список

```ts {8-14, 34-38, 41}
interface StructuredHeading extends ContentHeading {
  children: Array<StructuredHeading>;
}

export function structure(
  unstructuredList: Array<ContentHeading>
): Array<StructuredHeading> {
  const items = [];
  const list: Array<StructuredHeading> =
    unstructuredList.map((item) => ({
      level: item.level,
      text: item.text,
      children: [],
    }));

  for (let i = list.length - 1; i > -1; i--) {
    const item = list[i];
    let j = i - 1;
    let prev = list.at(j);
    let parent = null;

    if (prev && item.level > prev.level) {
      parent = prev;
    } else {
      while (prev && item.level <= prev.level) {
        prev = list.at(--j);
      }

      if (prev) {
        parent = prev;
      }
    }

    if (parent) {
      parent.children.unshift(item);
    } else {
      items.unshift(item);
    }
  }

  return items;
}
```

Ось, власне, і все! Ми перебудували список саме так, як
хотіли, і наступний логічний крок — відобразити його.

### Відображаємо список

Тепер, коли маємо деревоподібну структуру, рекурсивна логіка
здається очевиднішою, особливо якщо ми будуємо інтерфейс на
компонентах. Ось приклад на Qwik 👇

```tsx
export function RenderStructuredList(props: {
  list: Array<StructuredHeading>;
}) {
  if (props.list.length === 0) {
    return null;
  }

  return (
    <ol>
      {props.list.map((item, index) => {
        return (
          <li key={index}>
            {item.text}
            <RenderStructuredList list={item.children} />
          </li>
        );
      })}
    </ol>
  );
}
```

Ось і все, що потрібно: вкладений цикл і рекурсивний
компонент. Усе разом можна переглянути в [основному файлі
макета цього сайту][complete-example]. Заднім числом це
здається простим, і я думаю, що добрі розв’язки таких задач
зазвичай _справді_ прості в тому сенсі, що в них немає
складності. Але це не означає, що їх легко знайти!

## Для цього є плагін!

Звісно, найпростішим способом додати зміст до дописів мого
блогу було скористатися [плагіном rehype-toc][rehype-toc].
Якщо ти ще не користувався [плагінами rehype][rehype-plugins],
дуже раджу спробувати. Будь-яке перетворення виводу mdx, яке
тільки можна уявити, або вже покрите наявним плагіном, або
реалізовне у власному. На цьому сайті [один такий власний
плагін][clipboard-plugin] додає до фрагментів коду в
дописах кнопку копіювання в буфер обміну.

Плагін змісту [надає налаштування][rehype-toc-options], що
дають змогу налаштувати вивід як завгодно. Я підключив цей
плагін на ранньому етапі розробки блогу, але, читаючи
документацію Qwik, дізнався про [хук `useContent`][use-content-qwik],
який повертає впорядкований список заголовків. Саме тоді я й
упізнав ту саму задачу, яку мені дали на співбесіді багато
років тому. Одна з переваг даних від Qwik — свобода
розмістити зміст будь-де на сторінці й безпосередніший контроль над
тим, що насправді відображається.

## Висновок

Мені подобається писати про питання зі співбесід, які
здалися мені складними. Думаю, це допомагає мені готуватися
до майбутніх співбесід, і сподіваюся, що так само допомагає
читачам. Якщо пощастить, ти натрапиш на подібне питання в
майбутньому й згадаєш, як його розв’язати. Ось головні
висновки для мене:

- Не бійся просто змінювати дані в циклі. Не треба шукати
  рекурсивний розв’язок лише тому, що підозрюєш, що він є.
  Знайди найпряміший спосіб розв’язати задачу — можливо,
  згодом вдасться узагальнити його в елегантний рекурсивний
  вираз (а можливо, і ні, і це нормально).
- Почни з першого, що можна вивести, і будуй від цього. У
  цьому випадку ключ до розв’язку — зрозуміти, що
  батьківський елемент будь-якого елемента можна визначити,
  рухаючись списком назад.
- Навіть якщо ти займаєшся цим професійно 14 років і непогано
  вчився, ти можеш не побачити одразу правильного розв’язку
  простої алгоритмічної задачі. Намагайся не засмучуватися
  через це.
- Екосистема rehype чудова, і нею варто користуватися якомога
  більше. Будь ласка, не будь як я. Пожалій себе. Але я ні
  про що не шкодую.
- І так, цикли — це класно.
