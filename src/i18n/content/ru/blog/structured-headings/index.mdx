## Задача

В этой задаче нам дан упорядоченный список заголовков,
который нужно превратить в дерево для оглавления (Table Of
Contents, TOC) — вроде того, что показывается справа на этой
странице на широком экране. Допустим, у нас есть список тегов
заголовков в том порядке, в каком они идут на странице.

```ts
const orderedHeadings = [
  "h1",
  "h2",
  "h2",
  "h3",
  "h4",
  "h2",
];
```

Этот список нужно превратить в оглавление со структурой,
которая выглядит примерно так:

```ts
return [
  {
    tag: "h1",
    children: [
      {
        tag: "h2",
        children: [],
      },
      {
        tag: "h2",
        children: [
          {
            tag: "h3",
            children: [
              {
                tag: "h4",
                children: [],
              },
            ],
          },
        ],
      },
      {
        tag: "h2",
        children: [],
      },
    ],
  },
];
```

Возможно, ты гораздо более сильный программист, чем я, и уже
видишь довольно простое решение. Возможно, ты также знаешь,
что для контента в mdx [для этого уже есть
плагины][rehype-toc]. Но, конечно, в рамках этой задачи это
было бы жульничеством. Так как же решить её вручную?

## Решение

Мой большой программистский мозг часто убеждает меня, что
для любого преобразования списков существует рекурсивное
неизменяемое решение. Может, так и есть, но в этот раз я
такого не нашёл. Я потратил на попытки _очень_ много
времени, особенно учитывая, что оглавление у меня _уже было_
после подключения [плагина для mdx][rehype-toc]. Поэтому,
когда заработало решение с циклом и мутациями, я на этом
остановился.

В итоге я понял, что для любого заголовка в списке легко
просмотреть остальную часть списка и определить, каким
должен быть его _родитель_ или что родителя у него нет
вовсе. Если родитель найден, узел можно добавить в его
дочерние элементы. Вот... в общем-то, и всё.

### Примеры

Возьмём заголовки, которые идут на странице в таком порядке.

```plaintext
0 - h1
1 - h2
2 - h2
3 - h3
4 - h4
5 - h4
6 - h3
7 - h2
```

Кто родитель элемента с индексом 7? Это `h2`, поэтому нужно
лишь идти по списку назад, пока не найдём `h1`, — им
оказывается первый элемент списка.

А кто родитель элемента с индексом 5? Это `h4`, сосед `h4` с
индексом 4. У обоих один и тот же родитель — `h3` с
индексом 3.

У первого элемента списка родителя нет. Конечно, мы знаем,
что `h1` — заголовок верхнего уровня, но что, если бы в
нашем списке вообще не было тегов `h1`?

```plaintext
0 - h2
1 - h2
2 - h3
```

Посмотрев на элемент с индексом 1, мы должны заключить, что
это заголовок верхнего уровня, потому что, идя по списку
назад, мы не найдём элемент с меньшим номером заголовка. В
этом примере два узла верхнего уровня, а `h3` с индексом 2 —
дочерний элемент `h2` с индексом 1.

### Находим родителя

Теперь, когда задача стала понятнее, напишем код, который
пройдёт по списку и определит родителя. Вместо массива строк
вроде `h1` и `h2` у нас будут объекты со свойством `level` и
текстом заголовка `text`. Мы не будем проверять правильность
семантики заголовков: например, нашему коду всё равно, если
`h5` идёт после `h3`. Это мы оставим на совести автора
контента.

```ts
interface ContentHeading {
  level: item.level;
  text: item.text;
}

export function structure(list: Array<ContentHeading>) {
  // Loop backwards through the list
  for (let i = list.length - 1; i > -1; i--) {
    const item = list[i];
    let j = i - 1;
    let prev = list.at(j);
    let parent = null;

    // Start looking through the previous items. Keep going until
    // you find an item with a lower level than the current item.
    if (prev && item.level > prev.level) {
      parent = prev;
    } else {
      while (prev && item.level <= prev.level) {
        prev = list.at(--j);
      }

      if (prev) {
        parent = prev;
      }
    }
  }
}
```

Этот код найдёт родителя для каждого элемента, но ничего с
этой информацией не сделает. Давайте закончим: добавим
дочерние элементы родителям и вернём узлы верхнего уровня.

### Перестраиваем список

```ts {8-14, 34-38, 41}
interface StructuredHeading extends ContentHeading {
  children: Array<StructuredHeading>;
}

export function structure(
  unstructuredList: Array<ContentHeading>
): Array<StructuredHeading> {
  const items = [];
  const list: Array<StructuredHeading> =
    unstructuredList.map((item) => ({
      level: item.level,
      text: item.text,
      children: [],
    }));

  for (let i = list.length - 1; i > -1; i--) {
    const item = list[i];
    let j = i - 1;
    let prev = list.at(j);
    let parent = null;

    if (prev && item.level > prev.level) {
      parent = prev;
    } else {
      while (prev && item.level <= prev.level) {
        prev = list.at(--j);
      }

      if (prev) {
        parent = prev;
      }
    }

    if (parent) {
      parent.children.unshift(item);
    } else {
      items.unshift(item);
    }
  }

  return items;
}
```

Вот, собственно, и всё! Мы перестроили список именно так,
как хотели, и следующий логичный шаг — отобразить его.

### Отображаем список

Теперь, когда у нас есть древовидная структура, рекурсивная
логика кажется более очевидной, особенно если мы строим
интерфейс на компонентах. Вот пример на Qwik 👇

```tsx
export function RenderStructuredList(props: {
  list: Array<StructuredHeading>;
}) {
  if (props.list.length === 0) {
    return null;
  }

  return (
    <ol>
      {props.list.map((item, index) => {
        return (
          <li key={index}>
            {item.text}
            <RenderStructuredList list={item.children} />
          </li>
        );
      })}
    </ol>
  );
}
```

Вот и всё, что нужно: вложенный цикл и рекурсивный
компонент. Всё вместе можно посмотреть в [основном файле
макета этого сайта][complete-example]. Задним числом это
кажется простым, и я думаю, что хорошие решения таких задач
обычно _и правда_ просты в том смысле, что в них нет
сложности. Но это не значит, что их легко найти!

## Для этого есть плагин!

Конечно, самым простым способом добавить оглавление в посты
моего блога было воспользоваться [плагином
rehype-toc][rehype-toc]. Если ты ещё не пользовался
[плагинами rehype][rehype-plugins], очень советую
попробовать. Любое преобразование вывода mdx, которое только
можно представить, либо уже покрыто существующим плагином,
либо реализуемо в собственном. На этом сайте [один такой
самописный плагин][clipboard-plugin] добавляет к фрагментам
кода в постах кнопку копирования в буфер обмена.

Плагин оглавления [предоставляет настройки][rehype-toc-options],
позволяющие настроить вывод как угодно. Я подключил этот
плагин на раннем этапе разработки блога, но, читая
документацию Qwik, узнал о [хуке `useContent`][use-content-qwik],
который возвращает упорядоченный список заголовков. Тогда-то
я и узнал ту самую задачу, которую мне дали на собеседовании
много лет назад. Одно из преимуществ данных от Qwik — свобода
разместить оглавление где угодно на странице и более прямой
контроль над тем, что на самом деле отображается.

## Заключение

Мне нравится писать о вопросах с собеседований, которые
показались мне трудными. Думаю, это помогает мне готовиться к
будущим собеседованиям, и надеюсь, что так же помогает
читателям. Если повезёт, ты встретишь подобный вопрос в
будущем и вспомнишь, как его решить. Вот главные выводы для
меня:

- Не бойся просто менять данные в цикле. Не нужно искать
  рекурсивное решение только потому, что подозреваешь, что
  оно есть. Найди самый прямолинейный способ решить задачу —
  возможно, позже получится обобщить его в элегантное
  рекурсивное выражение (а возможно, и нет, и это нормально).
- Начни с первого, что можно вывести, и стройся от этого. В
  данном случае ключ к решению — понять, что родителя любого
  элемента можно определить, двигаясь по списку назад.
- Даже если ты занимаешься этим профессионально 14 лет и
  неплохо учился, ты можешь не увидеть сразу правильного
  решения простой алгоритмической задачи. Постарайся не
  расстраиваться из-за этого.
- Экосистема rehype прекрасна, и ею стоит пользоваться как
  можно больше. Пожалуйста, не будь как я. Пожалей себя. Но
  я ни о чём не жалею.
- И да, циклы — это здорово.
